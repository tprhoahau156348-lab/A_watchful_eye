# עין צופיה

## רקע

בשעה 06:25 התקבל בפיקוד מרכז דיווח חריג על חוליה חשודה שנעה לכיוון ציר תנועה מרכזי. שתי דקות לאחר מכן, ב-06:27, נקלט בפיקוד צפון דיווח עמום מיחידת רדואן: "היכונו ליציאה". ובשעה 06:29 נרשמה בפיקוד דרום התראה אדומה על תנועה חשודה בסמוך לקו הצהוב.
כיום, כל פיקוד רואה רק את הפיסה שלו בפאזל, מתייחס אליה כאל עוד "רעש רקע" מקומי וממשיך בשגרה. לכן הוחלט לפתח אפליקציה חדשה, "עין צופיה", שתרכז, תנטר, תסנן ותציג את כלל ההתראות המודיעיניות מכל הפיקודים בזמן אמת, כך שהחמ"לים השונים לא יפספסו  שום התראה קריטית.

### מטרת הפרויקט

אנחנו בונים כלי ברור ואמין שיעזור לצוותי הניטור והחמ"לים לנהל את המידע המודיעיני בצורה מסודרת ומהירה: לבנות תמונת מצב מדויקת, לעקוב אחרי כל התראה ולראות את הפיזור שלהן על המפה. בעזרת העבודה הזאת והמערכת שפיתחנו יהיה אפשר לחבר את חלקי הפאזל בזמן ולהתריע מפני איומים משולבים.
 כאן תוצג אפליקציית Full Stack לניהול תמונת מצב של ההתראות. האפליקציה תציג רשימת התראות ומפה, תאפשר להוסיף התראות חדשות ולמחוק קיימות, ותאפשר לחפש ולסנן ביניהן.

## אלה 4 ה-ENDPOINTS:

| Method | Route           | תיאור                                                                           |
| ------ | --------------- | ------------------------------------------------------------------------------------ |
| GET    | /api/alerts     | מחזיר את כל ההתראות                                                  |
| GET    | /api/alerts/:id | מחזיר התראה אחת לפי מזהה                                         |
| POST   | /api/alerts     | מוסיף התראה למסד הנתונים                                        |
| DELETE | /api/alerts/:id | מוחק התראה לפי id. חברו אותו לכפתור מחיקה בלקוח. |
| PUT    | api/alerts/:id/ | עדכון התראה לפי id                                                      |

## הוספת התראה חדשה:

בטופס ההוספה יהיו השדות הבאים.

| שדה      | סוג | תיאור                                         |
| ----------- | ------ | -------------------------------------------------- |
| displayName | string | שם או תיאור קצר של ההתראה      |
| description | string | תיאור מפורט של ההתראה            |
| priority    | string | רשימה נפתחת: Low, Medium, High, Critical |
| status      | string | רשימה נפתחת: Active, Handled  |
| arena       | string | רשימה נפתחת: North, South, Center        |
| lon         | number | קו אורך (longitude) להצגה במפה      |
| lat         | number | קו רוחב (latitude) להצגה במפה       |

## נימוקים והסברים

בחרתי להשתמש ב-MongoDB כי הוא נוח מאוד ונותן גמישות במבנה הנתונים.
קודי הסטטוס HTTP שהשתמשתי בהם:

- 200: בקשה טופלה בהצלחה.
- 201: התראה נוצרה בהצלחה.
- 400: שגיאת קלט מהלקוח (חסרים שדות).
- 404: התראה לא נמצאה.
- 500: שגיאת שרת.

הגדרות ולידציה: בשרת בדקתי שכל השדות הנדרשים קיימים בגוף הבקשה (displayName, description, priority, status, arena, lon, lat). אם חסר שדה, השרת מחזיר 400 עם הודעה מתאימה, כמו כן בדקתי שה-type של השדות הוא כדרוש ועם תווים (שהוא לא ריק).
